LisanHub

Language learning built by the people who speak the languages.

A community-driven platform where members create, review, translate and improve learning material. Every resource belongs to a language pair — the learner's comfortable language and the language they are learning — so a Kabyle speaker learning Turkish and a French speaker learning Algerian Arabic are first-class cases, not afterthoughts.

Status: early development. There is no public instance, no sign-up and no learning content yet. The code is published for transparency while it is being built, and nothing in it pretends otherwise: no demo lessons, no sample members, no invented numbers.

The idea

Most language apps are built for a handful of large languages and a single direction of learning. LisanHub starts from the other end: any pair of languages, chosen by the learner, and a community — not a central team — that writes the lessons, checks them, and carries them into other pairs by copying and adapting them with clear attribution to the original author.

The platform is entirely free in its first phase. Subscriptions and payments are deliberately left for a final phase, after real users have used the platform and said what works.

How it is built

No built-in kind of learning

Every activity type — exercises, vocabulary cards, anything that comes next — is a plugin: a declarative contract that describes its activities, its content schema and its editor fields. Contributors compose plugins in a studio inside the platform, without writing code.

Content is a file

A lesson is a portable package built for one plugin and stored as a single file. Copying, translating and rolling back a lesson are file operations with a provenance record, not rows scattered across a database.

A sandbox that never sees the user

Plugins and content run only inside an isolated frame with no network, no storage and no access to the page. No identity, progress or settings ever cross that boundary, and the authoritative score is recomputed on the server.

Accounts and files kept apart

Accounts and metadata live in a Postgres database with row-level security; every file — packages, pictures, plugin definitions — lives in object storage and is pinned by its hash.

Stack: Next.js, React, TypeScript, Tailwind CSS, next-intl, Supabase, Cloudflare R2, Zod, ts-fsrs, Vitest with PGlite. The interface is Arabic-first (right-to-left) with French and English.

What exists, what does not

Exists today: accounts, roles and administrative ranks with authorization enforced in code and in the database; language pairs over the full ISO 639-3 set; the plugin architecture with its studio, package format and sandboxed player; a content editor with versions, rollback and courses; an in-platform administration area with search-first oversight and moderation with a written reason.

Not yet: the learner experience (browsing, studying, spaced review, progress), derivation and attribution between members, community chat, ratings. They are next, in that order. The current state is kept honest in the repository's README.md and roadmap.

Contributing

Anyone may send changes: bug reports and ideas through issues, and code, documentation or interface-text improvements through pull requests. Open an issue before anything larger than a small fix — the architecture and the roadmap are deliberate.

A contribution is a voluntary gift, not a stake. Contributors keep the copyright of their own work and license it to the project owner, including the right to relicense it; a contribution creates no ownership, share, revenue right or say in the project's direction. The full terms are in CONTRIBUTING.md and are confirmed in every pull request.

Security problems go through private vulnerability reporting, never through a public issue.
