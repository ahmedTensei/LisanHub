# ADR 0007 — The plugin architecture toolchain: zip, a JSON Schema validator, sha256, and a small sandboxed player bundle

- **Status:** adopted (18 September 2026), implementing decisions R7 and R10 (ADR 0006) in S2.
- **Context:** ADR 0006 requires a `.lisanpkg` package (zip), a JSON Schema 2020-12 content schema per plugin, a sha256 hash that pins definitions and packages, and a player document that runs on an opaque origin under `default-src 'none'` and `connect-src 'none'`. These technical choices were not settled, and some of them are constrained by the licence (PolyForm Noncommercial does not accept GPL/AGPL/SSPL dependencies).

## Decisions

| Need | Choice | Licence | Why |
| --- | --- | --- | --- |
| Reading and writing zip | `fflate` | MIT | Small, synchronous, works in Node and the browser. Reading a package first goes through the central directory (`src/modules/packages/zip.ts`) to learn every entry's name, real size and mode (symbolic links) **before** inflating a single byte, so the limits apply before decompression |
| JSON Schema 2020-12 validation | `ajv` v8 (`ajv/dist/2020`) | MIT | The de-facto reference; it also validates the schema itself against the meta-schema (the "paste a JSON Schema" exit in the studio). Compiled validators are kept in a bounded cache keyed by the schema hash. Server only; the player does not need it |
| sha256 | `@noble/hashes` | MIT | The same implementation on the server, in the studio and in the player, without relying on `crypto.subtle` inside an opaque origin. The hash is computed over **canonical JSON** (sorted keys, no whitespace — `src/modules/plugins/hash.ts`) so it matches wherever it is computed |
| Bundling the player code | `esbuild` (development only) | MIT | `scripts/build-player.mjs` bundles `src/player/runtime/` into a single IIFE string in `src/player/runtime.generated.ts` with its CSP hash. The `/play` document embeds this string alone: no `_next/`, no cookies, no network requests |

### zod/mini in the modules shared with the player

The player validates the bridge messages with Zod schemas (ADR 0006 §5). The classic `zod` package adds about 450 KiB to the player document because it cannot be tree-shaken; `zod/mini` adds about 12 KiB. The modules the player imports are therefore written with the `zod/mini` interface (`z.string().check(z.minLength(1))` instead of the classic chains):

- `src/modules/content/levels.ts`, `src/modules/exercises/definitions.ts`, `src/modules/plugins/fields.ts`, `src/modules/plugins/contract.ts`, `src/modules/player/bridge.ts`.

Schemas built with `zod/mini` work inside classic schemas in the rest of the code (`.safeParse` and `.shape` are available). The result: the whole player document is **≈ 53 KiB** before compression, and is cached in the browser (`Cache-Control: private, max-age=600`).

### What the tests pin down

- The script hash in the CSP equals the hash of the embedded text, and there is no `unsafe-inline`, no `unsafe-eval` and no external reference in the document (`src/modules/player/document.test.ts`).
- No `fetch`, `XMLHttpRequest`, `localStorage`, `navigator.clipboard` or `eval` in the bundled player code.
- Every package rejection case in `src/modules/packages/packages.test.ts` (size, entry count, paths, symbolic links, the asset type from its bytes, hashes, schema conformance).

## Consequences

- Replacing any of these libraries later is confined to one module (`zip.ts`, `json-schema.ts`, `hash.ts`, `scripts/build-player.mjs`).
- `npm run check`, `npm run build` and `npm run dev` regenerate `runtime.generated.ts` first; the file is committed so that `tsc` works without an extra step.
- The two core plugins are produced by the studio pipeline itself (`scripts/core-plugins.ts` → `plugins/core/*.lisanplugin.json`) and their seeding migration is generated by `scripts/core-plugins-migration.mjs`; the test `tests/db/core-plugins.test.ts` verifies that what is seeded carries the hash of the exported file.
- Remaining risks: a hand-pasted schema with heavy regular expressions (`pattern`) may slow validation down; the `plugins.max_definition_bytes` limit and the review before publication contain it, and it stays under the eye of `platform-security`.
